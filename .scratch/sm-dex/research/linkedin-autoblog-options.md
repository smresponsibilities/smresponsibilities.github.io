# LinkedIn personal posts to Astro blog: options checked

Checked 2026-10-01. Target is a **personal profile**, not a company page. The site is static, so any import must run before an Astro build and commit data or trigger a new build.

## What LinkedIn officially allows

- LinkedIn's [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api) lists `r_member_social` for retrieving an authenticated member's posts, comments, and likes. It explicitly says this permission is **restricted** and available only to **approved users**. `w_member_social` is for publishing; it does not grant read access. `r_organization_social` reads posts for a company page on which the authenticated user has a permitted page role. Company access therefore does not solve this personal-profile case.
- LinkedIn's [User Agreement](https://www.linkedin.com/legal/user-agreement) forbids scripts, robots, browser plugins, and similar means used to scrape or copy services, including profiles and other data. Browser-session scraping can work technically, but a scheduled scraper using session cookies carries account and policy risk. Do not store LinkedIn cookies in this public repository.
- Official API path: apply for the relevant LinkedIn Marketing API product/permission, obtain OAuth authorization, query posts by author, then commit verified post records and rebuild Astro. Approval is the gating dependency. No basis to promise approval or automatic access from an ordinary sign-in.

- **Free, open source manual backfill:** [Aman-290/linkedin-post-scraper-extension](https://github.com/Aman-290/linkedin-post-scraper-extension) is MIT licensed and exports posts visible in a signed-in Chrome session from personal `/recent-activity/all/` to CSV. This directly fits recovering the user's older posts, subject to scroll depth and LinkedIn's scraping rule. It is not an unattended daily feed.
- **Free, open source JSON export:** [iwillsolo/LinkedIn-Activity-Scraper](https://github.com/iwillsolo/LinkedIn-Activity-Scraper) is Apache-2.0 licensed and uses Python, Selenium, ChromeDriver, and a LinkedIn username/password to scrape a profile's recent activity into JSON. Last pushed in 2023; login handling and current selectors need verification. Never put the account password in repository secrets for a speculative scheduled job.
- **Older browser experiment:** [adaOctopus/linkedin-activity-scraper](https://github.com/adaOctopus/linkedin-activity-scraper) says it opens Chrome, asks the operator to log in, then downloads about 30–40 recent posts/comments as HTML. No GitHub license was reported in repository metadata, so do not assume reusable code rights. It is a manual example, not a robust full archive.
- **Newsletter-only RSS:** [chrisns/linkedin-newsletter-rss](https://github.com/chrisns/linkedin-newsletter-rss) targets public LinkedIn newsletters. It does not solve ordinary personal feed posts. Many RSS-to-LinkedIn repositories found in GitHub search run in the opposite direction: RSS/blog → LinkedIn.
- [alexcerezo/linkedin-cards](https://github.com/alexcerezo/linkedin-cards) is a working scheduled GitHub Actions example. Its [LinkedIn client](https://github.com/alexcerezo/linkedin-cards/blob/main/lib/linkedin-client.js) calls an Apify profile-post actor with `username`, `page_number: 1`, and `limit: 25`, then filters returned posts by author. This shows a practical LinkedIn-first route without storing the user's LinkedIn login. It does **not** establish that every personal post is returned or that scraping complies with LinkedIn's terms.
- [Apify's profile-post actor](https://apify.com/apimaestro/linkedin-profile-posts) advertises public-profile posts without a LinkedIn account or cookies. It is a paid third-party scraping service; current plan and run charges must be checked before enabling a daily schedule. Test against known days 1233–1237: exact IDs, text, timestamps, and canonical URLs. A missed day or wrong author must not silently publish.
- [ismaelfi/Scrape-Linkedin-Posts](https://github.com/ismaelfi/Scrape-Linkedin-Posts) uses Selenium, ChromeDriver, BeautifulSoup, and pandas against a user's LinkedIn activity page, exporting posts to CSV. Its own README warns that LinkedIn bans automated scraping under its terms. Browser automation and page selectors make this fragile; the repo demonstrates extraction, not a safe unattended publishing service.
- [Aman-290/linkedin-post-scraper-extension](https://github.com/Aman-290/linkedin-post-scraper-extension) is a Chrome extension using the user's active LinkedIn login session. It visits personal `/recent-activity/all/` or company `/posts/?feedView=all`, scrolls, and exports CSV. This is a concrete, manual backfill technique, not unattended server automation; it also falls under LinkedIn's browser-plugin scraping prohibition.
- [christophe-garon/Linkedin-Post-Scraper](https://github.com/christophe-garon/Linkedin-Post-Scraper) covers company-page posts through Selenium. Its README warns LinkedIn changes its HTML and selectors. This implementation is useful evidence of maintenance cost, not evidence that personal profiles have an open read API.

## Recommendation for this portfolio

1. **Backfill now:** use the signed-in Activity page manually to collect canonical post URLs and original text. We already have verified IDs for days 1233–1237. Continue scrolling to older posts, checking each before adding it. This is finite work and avoids pretending a search index contains every post.
2. **For future posts, use the original content as source:** author the post in the repo or a small submission form first; publish same text to LinkedIn, then let existing Astro/GitHub Pages build publish blog entry. If LinkedIn remains the first and only source, a one-field post URL submission plus text review is the smallest reliable workflow.
3. **True LinkedIn-first unattended import:** two technical routes exist. Approved `r_member_social` access supports an official integration. A scheduled Apify scrape is faster to trial but incurs cost, can miss posts, and carries LinkedIn policy risk. A GitHub Actions `schedule` workflow can poll, commit verified records, and rebuild; scheduling alone does not confer LinkedIn access. See [GitHub's schedule docs](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
4. **Avoid cookie/session scraper in GitHub Actions.** It exposes an account credential to a scheduled runner, violates LinkedIn's stated scraping rule, and can break whenever login or markup changes. A paid RSS feed is worth a short exact-profile trial, but require known post IDs to appear with full text and stable canonical URLs before relying on it.

No final price quoted: actor and platform charges, quotas, and plans change; no current checkout or paid run was verified. Apify is a viable technical experiment, not a verified feed for this profile.

### Free/open source conclusion

For **past posts**, the MIT browser extension is the most concrete zero-fee path: export while signed in, compare day numbers and canonical URLs, and manually correct missing records. For **future unattended LinkedIn-first imports**, the free repositories found either require a logged-in browser/password or call a paid data provider. No verified free, open source personal-post feed with complete coverage was found. Build a no-fee reliable workflow by publishing the same source text to this Astro site and LinkedIn, or entering each LinkedIn URL after posting; automatic discovery from LinkedIn remains the hard part.

### LinkedIn account export checked in signed-in settings

On 2026-10-01, `Settings → Data privacy → Download your data` offered a **larger data archive** or selected categories: Articles, Invitations, Profile, Recommendations, Registration. It did **not** show a separate Posts checkbox. [LinkedIn's current help page](https://www.linkedin.com/help/linkedin/answer/a1339364) lists **Shares** in the larger archive: “all shared or re-shared posts,” including date, URL, shared comments, and visibility status. It says larger downloads arrive by email (overview says within 24 hours; category table labels availability within 48 hours) and links expire after 72 hours. Exact CSV column names and completeness for this account need inspection after the user's archive arrives. “100% accurate” cannot be asserted before that check; the archive is authoritative for whatever Shares records LinkedIn includes, and a diff can identify missing day markers within those records. Keep full archive private because it contains messages, connections, account history, and other personal data.
